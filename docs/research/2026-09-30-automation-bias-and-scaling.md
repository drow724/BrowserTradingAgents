## 개념

| 개념 | 뜻 | 성격 |
|---|---|---|
| Scaling Hypothesis | 규모 증가가 새로운 능력을 만들어낸다는 가설 | 이론적 출발점 |
| "Scale is all you need" / naive scalingism | 규모만 키우면 나머지 문제가 알아서 해결될 것이라는 강한 해석 | 설계 가정 |
| Machine heuristic | "기계니까 인간보다 객관적·정확·전문적일 것"이라고 여기는 인지적 지름길 | 사용자 심리 |
| Automation bias | AI 결과를 검증하지 않고 과도하게 따르는 현상 | 사용자 행동 |
| ELIZA effect | 유창한 언어를 실제 이해·사고 능력으로 착각 | LLM에서 특히 발생 |
| Techno-solutionism | 복잡한 문제도 기술 하나로 해결할 수 있다고 여김 | 사회적 개념 |

## BTA 적용

### 1. Naive scalingism

- 이미 있는 방어: Feature 016·017에서 확인한 오류(같은 숫자를 다른 뜻으로 쓰기, 근거 없는 전망)는 모델 크기와
  무관한 종류이고, FinanceBench에서도 큰 모델이 금융 수치를 많이 틀렸다. 결정적 checker가 모델 대신 근거를 판정한다.
- 적용: 클라우드 tier나 018 Benchmark에서 "큰 모델이 더 근거 있게 말한다"를 전제로 두지 않는다. 결과를 보기 전에
  가설로 등록하고 같은 checker로 검증한다.
- 에이전트 수도 같다. 역할을 늘리면 좋아진다는 것도 스케일링 가정이며, MAST는 그렇지 않을 수 있다고 본다. 역할
  추가에는 측정 근거가 먼저 필요하다.

### 2. Machine heuristic과 Automation bias

- 이미 있는 방어: 답변 창의 "근거 없음"·"의미 불일치" 표시, 모의 거래만 허용(MD-1), constitution VIII(투자 성과 주장
  금지).
- 빈 곳: 표시는 있지만 행동을 막는 장치가 없다. 근거 없는 claim이 있는 답변을 보고도 바로 모의 거래를 기록할 수 있다.
- 후보: 답변에 근거 없음·의미 불일치가 있으면 모의 거래 기록 전에 "이 답변에는 확인되지 않은 내용이 N건 있습니다"를
  한 번 보여 주는 가벼운 마찰 장치.

### 3. ELIZA effect

- BTA는 이 효과를 키울 수 있는 구조다. 8개 역할의 토론 형식과 JRPG 사무실에서 일하는 캐릭터가 "애널리스트 팀이
  검토했다"는 인상을 주기 쉽다.
- 적용: 캐릭터와 역할 이름 가까이에 "모델이 생성한 글"과 근거 확인 수를 함께 보인다. 최종 답변의 권위는 토론
  형식이 아니라 checker 결과에서 나오도록 화면 위계를 둔다.
- 연구 질문(현재 범위 밖, 사용자 실험 필요): 사무실 화면을 켰을 때와 껐을 때(`?viz=off`) 사용자의 신뢰나 거래 행동이
  다른가.

### 4. Techno-solutionism

- 이미 있는 방어: 최종 답변 정책 A-016-1("근거가 부족하면 부족하다고 말하라")과 비목표("투자 수익을 증명하지
  않는다"). "판단하기에는 근거가 부족합니다"를 좋은 답으로 인정하는 설계가 정면 대응이다.
- 적용: 측정에서 답하지 않은 것을 실패로만 세지 않는다. trap 질문 처리처럼 근거가 없을 때 멈춘 것을 성공으로 세는
  지표를 유지하고 넓힌다.

## 정리

| 개념 | BTA에 이미 있는 것 | 추가 후보 |
|---|---|---|
| Naive scalingism | 결정적 checker, 오류 유형 측정 | 모델·역할 확장 전에 가설 사전 등록 |
| Machine heuristic / Automation bias | 근거 표시, 모의 거래만 허용 | **모의 거래 전 확인 단계** |
| ELIZA effect | – | **역할·캐릭터에 "모델 생성"과 근거 수 표시** |
| Techno-solutionism | 근거 부족 정책, 비목표 | 근거 부족 답변을 성공으로 세는 지표 유지 |

굵게 표시한 두 항목은 로드맵에 "Trust calibration in the UI" 후보(after 017)로 등록했다.
